# Fallen Paths — agent / IDE notes

Godot **4.x** project. Primary language: **GDScript**.

- **Paths:** Use **forward slashes** in `res://...` preloads and when citing repo files (`combat/Foo.gd`). Git stores paths that way; on Windows a shell may show backslashes for the same path—there is only one file.

## Combat

- Orchestrator: `combat/CombatManager.gd` (instantiated by `ui/BattleScene.gd` using `ResourcePaths.COMBAT_MANAGER`).
- **Formation doctrine at `start()`:** optional `manager.encounter` keys `ENCOUNTER_KEY_FORMATION_DOCTRINE_PLAYER` / `ENCOUNTER_KEY_FORMATION_DOCTRINE_ENEMY` (else short aliases when canonical is empty; read **`CombatConstants.encounter_formation_doctrine_string`** → **`formation_doctrine_string_from_dict`**), then optional preset fields `FORMATION_PRESET_KEY_DOCTRINE` or `FORMATION_PRESET_KEY_DOCTRINE_ALT` on each `start(player_formation, enemy_formation)` dict (preset overrides encounter per side; preset read **`CombatConstants.formation_doctrine_string_from_dict`**). Optional depth-spear AI doctrine mults: encounter **`ENCOUNTER_KEY_DEPTH_POLEARM_AI_MULTS_PLAYER`** / **`ENCOUNTER_KEY_DEPTH_POLEARM_AI_MULTS_ENEMY`**, preset **`FORMATION_PRESET_KEY_DEPTH_POLEARM_AI_MULTS`** (preset wins); merged dict per formation at **`start()`**, read via **`CombatManager.get_depth_polearm_ai_doctrine_mult`**. Harnesses **`CombatRegressionHarness._run_encounter_formation_doctrine_on_start`**, **`_run_encounter_formation_doctrine_string_helper`**, **`_run_depth_polearm_ai_doctrine_mults_encounter_preset`**.
- **Health / wounds node:** `CombatManager.get_health_entity(node)` — combat subsystems should use `CombatantEntityAccess.get_health_entity_from_node(manager, node)` or `get_entity_from_manager(manager, combatant)` (not `_get_entity` from outside the manager).
- **Formation dict keys (file index as int or string):** `CombatFileKeyedDict.get_value` and `FormationBreachRules.breached_file_severity` where relevant.
- Gameplay logic is split across `combat/*.gd` modules (tick, events, formation, engagement, snapshot, medical coordination, etc.); see `.cursor/rules/fallen-paths.mdc` for a fuller map. **`ZoneOfControl.formation_dict_for_zone_geometry(manager, combatant)`** returns **`manager.formations[fid]`** for **`formation_id_for_zone_geometry`** (read-only; use instead of ad-hoc `formations.get` when posture, **`breached_files`**, or crash AI weights must match the tactical line). **Crash contest** (`BreachResolver`) and **neighbor hold** (`CombatIntrusionGeometry`) use **`ZoneOfControl.formation_id_for_zone_geometry`** for the defender’s formation dict + flank allies when the defender is an **intruder** on a host line. **`CombatEventScheduler`** (back-rank recheck + rank/file snapshots), **`AvailableActionsBuilder`** (swap partners / host **`our_formation`** / depth-spear lane dicts / same-file rank-0 ally), **`CombatResolveAction`** (formation-move formation dict), **`AttackResolver`** (depth density log), **`CombatFormationFlow.on_combatant_died`** (corpse **`slot_obstacles`** + death micro-plug + `notify` on host vs home), **`CombatEngagementResolver.resolve_close_attempt`** (defender density), and vacancy **`_combatant_from_slot_primary_living`** / compact blocking use the same geometry where **`rank`/`file`** sit on the host grid.

## Core / UI

- Entity model: `core/` (e.g. `CoreEntity.gd`, `EntityDamage.gd`, …).
- Battle UI: `ui/BattleScene.gd` and related `ui/*Battle*`, `ui/*Combat*`, `ui/*Formation*` — optional 5th arg **`p_encounter`** or world meta **`CombatConstants.WORLD_META_COMBAT_ENCOUNTER`** (see **`CombatFlow.start_combat`**) seeds **`CombatManager.encounter`** before combat **`start()`**.

When changing combat flow, prefer editing the **focused module** rather than inflating `CombatManager.gd`.

Debug: `COMBAT_EVENT_DEBUG` enables turn-summary `[Combat.Flow]` lines; add `COMBAT_EVENT_DEBUG_VERBOSE` for per-action lists and formation/incursion spam (`CombatConstants.gd`). Player lead is flagged on `Character` via `is_party_leader` (scene + `PlayerCompanionSetup`); combatants carry `is_party_leader` from `CombatManager.register`. Headless harness: `godot --headless --path <project> -s res://scripts/run_combat_regression_harness.gd` → `CombatRegressionHarness.run_all()`. In this repo, set **`godotTools.editorPath.godot4`** in **`.vscode/settings.json`** (Godot Tools) and run the VS Code task **Run Combat Regression Harness (headless)** from **`.vscode/tasks.json`**.
